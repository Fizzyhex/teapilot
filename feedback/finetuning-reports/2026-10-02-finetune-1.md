## diagnosis

- Original production failure: 30 calls rereading historical junior evidence, no current app inspection, delegation, or task-state updates; no plan.
- Current target is the reverted floor/wall MVP. Historical door code is not current source or an authoritative upstream reference.
- Explicit task identity originally scoped snapshots but not replayed tool histories and pi compaction summaries.
- Simulator Discord stores were isolated, but host inference still used production state and its run lock. An early comparison was blocked by that lock.
- Successful source discovery still does not ensure bounded planning: the source-backed run consumed 40 calls on listings and reads without synthesis.

## changes

- Automatic bounded source observations, prioritizing direct files and discovery over saved outputs/transcripts; paginated record discovery.
- Source-origin notices on historical capture reads and initial workspace inventory.
- Host-enforced read-only proposal tools, inherited by juniors; request-local mode and uncluttered task objective.
- Task-scoped tool-history replay and compaction selection; prior conversation text remains available.
- Partial junior call allocations, leaving instructor review capacity.
- Repeated read-only inspection withdraws tools for synthesis; near-exhausted exploration also reserves a synthesis/report turn.
- Simulator host state isolation and evidence capture of task snapshots.

Upstream `Door.ts` treats `exitDoor` as a special door; separate `Lever.ts` interaction ends the level. These are semantic failures despite host completion status.

The final reserved-synthesis run produced a materially better plan, but not a full acceptance pass: it proposed `Map` for JSON-persisted state, left data loading conditional on runtime support, and did not resolve how open-door glyphs remain visible when raycasts skip them. Both juniors reported stuck. Telemetry records 31 instructor calls and 7 junior calls; Discord's displayed 41 steps is not the executed-tool count. This one run establishes that synthesis can complete after exploration, not repeatability or efficiency.

No efficiency improvement is established. Early captures showed 389,183 versus 416,775 reported inference input-plus-cache tokens and peak payloads of 62,153 versus 63,992 bytes, but those runs differ in execution completeness and patch provenance. Capture-time patch hashes are not reliable startup fingerprints when edits occur during a run.
