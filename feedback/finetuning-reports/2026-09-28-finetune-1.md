I ran ScratchBench (`scratchpad-challenge.md`) and Case 1U (Kessel Sabacc) three times each against the local Qwen 27B (32k context) in the Discord simulator, on the `feat/scratchpad` branch (PR #16). I fixed what each run exposed before the next one, so later runs had more fixes than earlier ones. After two of the fixes I added one verification run: ScratchBench 3b and Kessel 4. Nothing prompted teapilot to use the scratchpad; every prompt is the one in the case files.

**Summary.** The scratchpad does what it is meant to do on ScratchBench:
- The diagnostic ran once in every run.
- Its full output was kept.
- Every later stage found the omitted record through one exact-ID search of the saved file.

The failures were around it. A path mix-up made the first search fail. A repeated edit loop wrecked a cosmetic update. The model would not trust a complete search that found no success event. All three have general fixes now. Kessel Sabacc never needed retrieval: the model built from its own rules summary, and its problems are game logic, not memory.

## ScratchBench

Seeds `sb-2609-a`, `-b` and `-c` come from `scripts/bench/import-diagnostic.mjs` (fixture `import-diagnostic/1`), and each has about 10,000 lines. Run 1 used `--history-tokens 4000` as its boundary. Runs 2–3b used `--compact-history`, which is new. Every run had the scratchpad on; I did not run the clipping-only baseline.

| Run | Seed | Stage 1 (build) | Stage 3 (targeted question) | Stage 4 (rename) | Stage 5 (reuse) | Diagnostic calls | Stage-3 retrieval | Verdict |
|---|---|---|---|---|---|---|---|---|
| 1 | a | ✅ 24s | ✅ 50s, but attempt 1 failed (`.scratch/outputs` not found) and escalated | ❌ 26s, edits missed, tools withdrawn, nothing changed | ❌ said "success", but the probe is **invalid**: the history cap had dropped stage 3 | 1 | 1.4k chars (+2 failed calls) | Incorrect |
| 2 | b | ✅ 23s | ✅ 23s, one search | ✅ 7s | ✅ 3s, no tools | 1 | 1.4k chars | **Pass** |
| 3 | c | ✅ 23s | ❌ 26s, context limit after 10 retrieval calls | ✅ 6s | Right answer after 10 more searches and an escalation (the finding had never reached context) | 1 | 35.7k chars | Incorrect |
| 3b | c | ✅ 19s | ✅ 52s, 6 calls, one escalation | ✅ 6s | ✅ 4s, no tools | 1 | 8.7k chars (~2.4k tokens) | Correct but inefficient |

- **Evidence correctness.** Runs 1, 2 and 3b match their manifests exactly: the initial failure detail, retry attempt 2, the final outcome, and the terminal and initial-failure event IDs. Run 3 found the evidence but never finished the turn.
- **Retrieval demonstrated.** The traces show each answer came from `search_files` on `outputs/run_import_diagnostic-1.txt`. Each stage's preview never contained the target record, and the boundary compacted the diagnostic result to 400 characters plus its saved-file line.
- **Refresh** worked in every run without calling the diagnostic again.
- **Why run 3 went wrong.** The first search returned all six events (`truncated: false`). The model then kept looking for a success event that does not exist: the same search with bigger limits, then 200-line reads. The old search note ("Scan complete within scope…") never said the matches were complete. Run 3b, with the clearer note, finished correctly but still double-checked once too often.

## Case 1U: Kessel Sabacc

The prompts were:
1. The same research request.
2. "looks right! skip the shift tokens and cheating. now implement … for me and @user, 6 chips each." Run 1 also corrected a rule its research got wrong.
3. The same correction naming the problems found in play.

The game score is out of 10. It covers the deck, hidden hands, draw and keep choices, turns, turn ownership, Impostor and Sylop, ranking, chips and penalties, and whether a round plays through. It is taken after the correction.

| Run | Research | Build | Correction | Pages kept | Game |
|---|---|---|---|---|---|
| 1 | 49s; called a 3+2 hand a Sabacc | 1m47s | ❌ context limit (2m20s) | none (only truncated pages were kept) | 2 |
| 2 | 55s, correct, 3 sources | 1m11s | ✅ 1m15s | 3 pages | 4 |
| 3 | 56s, correct, 3 sources | 1m27s | ✅ 1m22s | 3 pages | 5.5 |
| 4 (checked the prompt tweak) | 47s | 1m15s | — | — | hands still public |

- **What improved.** Research now keeps every page it reads, and the correction turn no longer runs out of context. After correction, runs 2–3 enforce whose turn it is and tax correctly. Run 3 lets the player keep the new or the old card.
- **What never worked.** Hands are in the shared message in all seven builds, even when asked to make them private: the model shows "the current player's hand" in the shared view. There's no Impostor dice choice, drawing from a discard pile is missing or broken, and every build's first `play_start` had no code block.
- **Scratchpad.** There were no reads in any build or correction turn. The rules the model needed were in its own reply, which later turns keep, so retrieval was never the bottleneck here.

## Fixes (all general)

| Found in | Problem | Fix |
|---|---|---|
| ScratchBench 1, stage 3 | The prompt calls the folder `.scratch/` for `workspace_run`, but the file tools were rooted at the scratchpad, so `.scratch/outputs` meant `.scratch/.scratch/outputs` | `ExecutionPolicy.resolve`: `.scratch/…` means the scratchpad for every file tool, in either kind of session |
| ScratchBench 1, stage 4 | After compaction the model guessed `find` text three times and gave up | A find that matches nothing now shows the closest lines of the current source and points to `play_inspect` |
| ScratchBench 1, stage 5 | With earlier turns dropped, the model made up an answer | When `fitHistory` drops turns, the first kept message says how many are not shown |
| Kessel 1, research | `web_read` kept only pages too long to show, so a 9 KB rules page was lost to later turns | Any page longer than later turns replay (2,000 chars) is kept under `pages/` |
| Kessel 1, correction | Three large `play_update` edit sets stayed in context and filled 32k | Within an attempt, superseded play calls that changed nothing are cut down. Under context pressure, earlier applied ones and their code blocks are too. The newest call is never touched. The context-limit message now says "largest tool call" (arguments and result) |
| ScratchBench 3, stage 3 | The search note never said the matches were complete | A complete search says "These are all N matches in scope" (and "the text does not occur there" for none). An identical repeat says searching again will find nothing more |
| Benchmark | `--history-tokens` also drops whole turns, which invalidated stage 5 | `--compact-history` (`TEAPILOT_TEST_COMPACT_HISTORY=1`) compacts every earlier turn without dropping any |

I tried one prompt change and reverted it: "never in the shared view, which everyone sees whatever the turn". Kessel 4 still put the hand in the shared view.

## Still open
- **Over-checking an absence** (ScratchBench 3b): the model still searched more than once, and the repeat detector escalated. Retrieval was about 2.4k tokens against the 2,000 target.
- **Hidden information in `discord.play`:** hands leaked in seven of seven builds, and prompt wording doesn't change it. Something structural may be needed, such as the dry run flagging a view that shows per-player state.
- **Player choices** (Impostor dice, which discard pile), and the first `play_start` without a code block, which wastes a step in every build.
- **Baseline, restart and forced-retry variants:** not run. The spec's five-seed matched comparison with `--scratchpad off` is the next step to measure the scratchpad's benefit rather than its plumbing.
- **Simulator state:** simulator runs write their events to the profile's `outcomes.jsonl` (`~/.teapilot`), not the session's state folder.
