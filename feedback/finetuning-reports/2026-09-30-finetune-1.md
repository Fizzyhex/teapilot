I ran the orchestration challenge (Case 1O, Greggs Kiosk) against the local Qwen 27B (32k context) in the Discord simulator: `/plan`, then `assign juniors`, then `lgtm!`. The runs were run 0 on the old prompt wording, a baseline on the updated prompt, and six runs with fixes (runs 1–8, with runs 1, 2 and 5 cut short). I fixed what each run exposed before the next, so later runs have more fixes than earlier ones. The apps are in [the game catalog](../game-catalog/README.md).

**Web search was down for every run.** searxng was running, but brave and Google CSE were suspended for too many requests, DuckDuckGo returned a CAPTCHA and wikidata timed out. So `web.search` never became active. Workspace commands could still fetch pages once I approved each host. Run 3 got the nutrition PDF that way, but no run turned it into correct data. Nutrition accuracy is 0 in every run, and I have not scored that against the model.

**Summary.**
- **Plans are better.** They now make collecting the data from the linked pages the first step, use UK traffic-light thresholds and emoji for the middle colour, and ask better questions. In run 3 onward, no run started implementing early.
- **Delegation is better in most runs.** Four of five runs grouped the work as one data junior plus the app, instead of three juniors editing one file.
- **Juniors can now build apps properly and report before running out of tool calls.**
- **What still decides the outcome is outside these levers.** The model often reads its own transcript until the context fills. Briefs to juniors drop the plan's sources, and the model then invents data.

## Still open
- **The model reads its own transcript.** In every run the plan or build turn listed `.scratch/`, then opened `.scratch/sessions/<id>.jsonl` (its live transcript) looking for "what you have downloaded". It cost run 2 a whole attempt and caused run 8's context limit. A general fix would have `read` answer "this is your own transcript; it is already in your context" for the current session file, or hide `sessions/` from `ls`. It's in the scratchpad, outside the orchestration path, so I left it.
- **Briefs don't carry the plan's steps.** Plans say "fetch greggs.com/…", but the `delegate_task` messages list invented items instead. Wording hasn't fixed this. Something structural might, such as the build turn seeing the plan's TODO for each junior next to its brief.
- **Invented facts about a real business.** The model took Greggs for a Canadian or Middle-Eastern chain (pitas, poutine, knafeh). In run 3 it also presented invented values as coming from the PDF.
- **No PDF text tool in the workspace.** Run 3's junior downloaded the nutrition PDF but has only Python without PDF libraries, and failed to parse it in 120 calls.
- **Plans still include a separate data module and "import or inline"**, although sandboxed apps can't import. The build notices and inlines it, at the cost of a few steps.
- **"Web search was unavailable" repeats** on every later reply and gets echoed twice in some messages, because the note enters the history and the model copies it.
- **Plan buttons don't survive a restart** ("This plan is no longer available"), so run 5 could not continue after I restarted it to load a prompt change.
- **Unrelated:** `tests/chat.test.ts` and `tests/discord-oneshot.test.ts` fail on `main`. `workspace/commands.ts` says "note: the workspace still contains…", but the tests expect "The workspace still has…".
