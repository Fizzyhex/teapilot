This run acted on the findings in `2026-09-27-finetune-3.md` and then ran the conversation challenges (Case 1C: Casual Switching, Case 2C: Banter) four times each against the local model (Qwen3.8-27B heretic).

## Finding 0: trials were never isolated

Before the fixes could be measured, it turned out that `agent-discord.mjs restart` does **not** start conversations over. Discord history is saved (`~/.teapilot/discord-history`) and reloaded on restart, so every "fresh" trial in finetune-3 and in this run's first round still had the earlier trials in context. Two symptoms showed this:

- Leeds, Austin and Cardiff fast-food answers were word-for-word copies of the earlier Nashville answer, with 0 steps.
- A Glasgow venues answer listed Edinburgh venues taken from an earlier Edinburgh weather question.

So finetune-3's "same stock line in all six trials" finding, and possibly its hallucinated list, were at least partly caused by history leaking between trials. Trials now say `/clear` between runs. Two notes on that: with Git Bash, set `MSYS_NO_PATHCONV=1`, because it otherwise rewrites `/clear` into `C:/Program Files/Git/clear`. The simulator's help text for `restart` was also out of date and has been corrected.

The first round is discarded. The scores below are from the clean second round.

## Changes

- **Search that needs no approval is always offered** (`host.ts`, `SessionGrants.free`). In Discord, `web.search` is pre-approved, but it was only switched on when Jev confidently named a search basis, so a missed basis left the model answering from memory. Now, if search needs no click for the caller, the tool is offered on every non-casual turn, and the model's volatile-fact policy decides whether to call it. Covered by a new test in `search.test.ts`.
- **No invented sources** (`ask.ts`). The prompt for turns without web access now says never to list sources or links it did not read.
- **Casual prompt** (`casual.ts`). New rule: reply to what was actually said; when teased or insulted, clap back playfully using their own words or what they just asked, and never explain your own personality. Also fixed the third example, which used a real newline instead of `\\n`. A trial clap-back example was removed again, because the model copied it word for word in all four trials.
- **Routing questions** (`intent.ts`). `conversation.task` now excludes explanations about teapilot itself, and `conversation.personal` includes "the way it talks". This targets the 1C step 3 misroutes below. **It was not trialled** because it was made during the final round.
- `casual.test.ts` now checks the system message against `casualPrompt()` instead of an old copy of the example lines, which had already gone out of date.

## Still open

- **Clap-back quality.** The replies now engage with the insult, but 2/4 still describe the persona ("brainy nerd") instead of teasing back. The identity line is the likely anchor. Adding examples is risky on this model because it copies them word for word, so a rule-only approach or a less concrete identity line are the next things to try.
- **1C step 3 routing.** The `intent.ts` change has not been tested live yet.
