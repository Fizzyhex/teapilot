I ran the three ultra challenges (1U Kessel Sabacc, 2U library abyss, 3U freestyle) against the local Qwen 27B with a 32k context, scoring response time, accuracy and completion. Each challenge ran once on the original code (baseline) and three times on the tuned code (final runs), plus six iteration runs while tuning that are not in the scores. Across the final runs the average score went from 3.3 to 5.9 out of 10, and 26 of 27 turns completed, against 6 of 9 before.

The final runs were not all on identical code: I kept fixing bugs they exposed, so later runs had more fixes than earlier ones. Typecheck passes and all 419 tests pass on their own. Under full parallel load, one or two unrelated tests time out (consult cap, access grants, one-shot history); the original code fails the same way, so that flakiness predates this work.

For 3U I picked a co-op farming game in five turns: a 5×5 farm for two players, a seed shop dropdown, AI-written weather forecasts each in-game morning, crows that eat crops unless scared off, and a leaderboard.

## Main findings and fixes

**Harness**
- **Early escalation:** `play_*` tools read their code from the reply, so every retry had identical arguments. The repeat detector treated honest fixes as repeated calls and escalated. It now judges play tools by their results.
- **Thinking tiers:** every tier is the same model on this setup, so escalation only adds thinking. The reasoning and deep tiers hit their output limit mid-thought in every run that reached them, costing 5–15 minutes. When play calls stop making progress, or an attempt reaches its last turn, tools are now withdrawn and the model answers with what is live.
- **Half an emoji:** trimming older turns to fit the context could cut an emoji in half, and TabbyAPI then fails the whole request (`TextInputSequence must be str`, HTTP 500). Trimming is now emoji-safe, and every request is cleaned before sending.
- **Reply space:** `discord.play` attempts reserve 8,192 output tokens instead of the normal tier's 4,096, since the reply carries the whole app.
- **Web search:** SearXNG's default engines were rate-limited or blocked, so research failed outright; Bing and Yahoo return unrelated spam to it. When the defaults all fail, search now tries Google, DuckDuckGo web, Yep and GMX. It only counts as an outage when every fallback engine fails, and it returns 8 results instead of 5.

**Play tools**
- `play_start` takes `edits`, so a rejected app is fixed with find/replace instead of regenerating 3,000 tokens; its title is optional then.
- `play_update` edits after a rejection apply to the rejected version first, then to the running source.
- `play_test` dry-runs the code as last edited, not a stale code block. After `play_update` it starts from the running app's state, and it reports how many actions changed nothing, which visibly drove fixes.
- `play_update` takes `timers` to start a loop in an app whose `init` and start button already ran. The probe note for such loops now points there, instead of advising `init`, which the model then edited to no effect.
- `play_inspect` leaves out source identical to the code block in the reply.
- Participant lists read `"invoker"` and `<@id>` entries and always include whoever asked. Bad lists are turned away before any code is tried, so they don't count as rejected code.
- Syntax errors show the line with a caret.
- Long apps posted without a dry run get a nudge to play a round through.

**Checks and runtime**
- **Dead views:** an app whose view has no controls and nothing scheduled is rejected, since no one can do anything with it.
- **Unscheduled timers:** timers that no control or pending timer ever schedules are flagged.
- **Duplicate IDs:** buttons repeated per player under one ID get unique custom IDs on Discord and still reach the app under that ID. IDs may contain `:`.
- **New state fields:** on update, top-level fields the new `init()` adds are filled into the kept state.
- **Consult replies:** an answer wrapped as `{"text": …}` when plain text was asked for is unwrapped.
- **SDK:** `text()` accepts arrays of lines; the model passed arrays and got an empty description.

**Prompt changes** (all general, none aimed at a specific case)
- The size limit allows games with many rules (up to 300 lines).
- Every rule belongs in `update()` and state, not only in the view.
- Rule-heavy games start with the rules as comments, players make their own choices through controls, and turn-based games track whose turn it is.
- Private information goes through `ephemeral()`, never the shared view.
- Generated worlds stay walkable.
- A rejected app is fixed with edits rather than rewritten.
- A new timer loop in a running app is started with `play_update` timers.

## Still open
- **Kessel rule fidelity:** the model still drops rules, leaks hands and gets chip accounting wrong. A probe that plays a whole round with both players would catch rounds that never end.
- **Dying timer loops:** Final 3's farm stopped ticking at the first in-game morning, because that branch returned without rescheduling. The probe could run timers on a simulated clock for a few minutes and flag loops that stop.
- **Live state changes:** changing a starting value (coins) for players already in the game needs a way for an update to change the kept state, such as a one-off migration step on `play_update`.
- **Gap logic:** two of three library runs teleported from the pre-step position; dry runs that walk into each gap would catch it.
- **Research depth:** research only sees search snippets. A page-reading tool would help a lot but needs SSRF safeguards, so I did not add one.
- **Search setup:** new SearXNG installs could enable the engines that still answer, rather than relying on the fallback.
