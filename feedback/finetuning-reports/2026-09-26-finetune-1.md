## Main findings and fixes

**Tool loop**
- **Calls without code:** the fastest routing tier doesn't think first. It called `play_start` with no code block and repeated the same call up to three times. After a call with no new code, tools are now paused for one reply, so the model has to write the code, then they come back. This took Case 2 from three failed attempts to one wasted call.
- **Resending failed code:** sending the code that was just rejected, unchanged, now gets turned away and triggers the same pause.
- **Lost tool calls:** the model server sometimes signalled a tool call but sent none, and the turn ended as an unexplained "incomplete". The attempt now asks again, up to twice, before escalating.
- **Escalation prompt:** it always said "existing edits are still in the repository", which sent a model thinking for 60k characters about repository access for a Discord game. It now mentions edits only when there are some.
- **Diagnostics:** failed attempts now record how the model's last message ended. That is how the lost-call bug was found.

**Checks before an app is posted**
- **Timers:** apps that handle timers but never schedule one are flagged. The minimum timer is now 2000 ms, matching what the prompt already said; the model had been settling on the old 1000 ms floor.
- **Dead controls:** apps where no control changes anything, such as a game nobody can join, are flagged.
- **Shortcodes:** `:shortcodes:` in any view are flagged, since Discord only converts them when a person types them. `ctx.emoji()` falls back to `:name:` text, which is how `:man_fairy:` ended up on screen.
- **Embed shapes:** `footer: { text }` and `image: { url }` (Discord's own shapes) are now accepted.

**Consult answers**
- The consult model repeated its JSON answer twice, so the app's `JSON.parse` failed and the recipe vanished. When a consult asks for JSON, the app now gets the first complete JSON value in the answer.

**Prompt changes** (all general, none aimed at a specific case)
- Tick from the control that starts a round, not from `init`.
- `step(state, after(...))` is the only way to return effects.
- Generated content must come from `consult()`, never hard-coded.
- Consult ids are fixed names.
- Dry-run rules involving several people or steps, then compare the returned preview with the request.
- Dropdown options can have a `description`.
- Keep tool errors out of the answer people see.

**Tool arguments**
- The `emojis` argument no longer invites invented custom-emoji IDs; the model had fabricated IDs for `:man_fairy:` and friends.
- `participants: ["everyone"]` is now accepted as `"everyone"`.

**Simulator**
- `start --frozen` stops the clock, so fast games can be played step by step; I noted it in AGENTS.md.
- The screen now shows dropdown options' emoji and descriptions.

## Still open

- The model still gets game rules subtly wrong at times, for example overlapping players when stacking in run E.
